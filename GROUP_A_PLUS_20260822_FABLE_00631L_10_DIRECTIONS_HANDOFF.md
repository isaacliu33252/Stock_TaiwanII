active_2025_2026).

delta_vs_baseline final_value match to the cent) against a fresh re-run of
the original script's `00631l_only` mode under the same policy -- confirms
the new implementation is correct. (Absolute dollar figures differ from the
2026-08-21 handoff's own numbers for nominally the same config because
`group_a_plus/runners/latest.py`'s underlying production strategy state kept
evolving in the uncommitted working tree across the session; this does not
affect the within-run cross-cap-fraction comparison.)

**Result**: average delta_vs_baseline final_value is monotonically less
negative as cap_fraction shrinks (0.25: -$123,109.94, 0.5: -$159,471.76,
0.75: -$195,625.06, 1.0: -$231,451.22 -- roughly linear, ~-$140k per unit of

## Direction 10: Quadratic bound as a backward-looking risk-budget guard

**Original framing** (the most structurally different of the 10, explicitly
flagged as needing its own backtest before any promotion consideration): use
`letf_quadratic_bound.py`'s certified (m1,m2) formula (arXiv:2301.03186
Theorem 1/Remark 2) as a deterministic risk-budget sizing/floor calculator
conditioned on the ALREADY-REALIZED trailing window, not a forecast.

**Distinguished from already-closed work**: `GROUP_A_PLUS_20260810_2301_
03186_QUADRATIC_BOUND_REGIME_CROSSCHECK_HANDOFF.md` already used the same
formula as a FORWARD crosscheck of `leveraged_compounding_regime.py`'s
TREND_PERSISTENT/MEAN_REVERTING path-shape classifier against *future*
(m1,m2), and found no robust lift after correcting pseudo-replication. That
prior handoff's own postscript (section 9) explicitly flagged "certified
bound as a backward-looking risk-budget/stress-test tool" as the one
residual, untried use -- forecasting future (m1,m2) from past path shape is
mathematically unrelated to the realized value (cumulative log-return
depends only on the {Yi} multiset, not order), but using a trailing window's
own realized (m1,m2) as a same-scale near-term volatility estimate is the
standard, well-documented volatility-persistence assumption, a different and
more defensible premise than the already-refuted path-shape-persistence one.

**Method**: new script `backtest_group_a_plus_quadratic_bound_risk_budget_
guard.py`. Using only the trailing 60 trading days of realized 0050
log-returns (shifted 1 day, no same-day lookahead), computes the certified
quadratic lower bound on 00631L's n-day cumulative log-return (leverage=2.0,
y0=Taiwan's daily +-10% limit, matching the y0 anchor from the 2026-08-10
crosscheck) and compares it to the trivial 1x reference (n*m1, i.e. what
holding 0050 outright would have returned over the same realized window).
Guard fires (shifts 00631L weight fully to 0050, cap_fraction=1.0 mechanic
reused from direction #9) when the certified 2x worst-case floor is below
the 1x reference. Trigger frequency checked before running the full backtest
(36-41% across window sizes 20-90, not degenerate). Tested only
cap_fraction=1.0, not swept, since this is a brand-new untested trigger and
stacking an untested cap-size sweep on it would conflate which dimension
drives any result.

**Result**: `do_not_promote_keep_shadow` in every window.

| Window | Warning days | Δ final value | Δ Sharpe | Δ MDD |
|---|---|---|---|---|
| full_2016_2026 | 795 | -$755,878.62 | -0.0512 | +0.0139 |
| rate_hike_2022_2023 | 269 | -$20,889.09 | -0.0859 | -0.0004 |
| live_2024_2026 | 121 | -$84,192.70 | -0.0335 | 0.0000 |
| active_2025_2026 | 91 | -$27,241.30 | -0.0361 | +0.0006 |

Every window loses on final value and Sharpe, while MDD is flat or only
marginally improved -- a bad risk-adjusted trade (giving up real upside for
negligible downside protection). Theoretically consistent explanation: the
quadratic bound is a WORST-CASE guarantee, not an expected value, so its
being below the 1x reference does not mean the actual forward realization
will underperform -- it fires whenever trailing volatility is elevated
enough that the *guaranteed floor* fails to clear 1x, which happens far more
often (36-41% of days) than 00631L genuinely underperforms 0050 going
forward, a structural false-positive-rate problem with using a worst-case
bound as a point-in-time trigger. **closed_negative**.

**Standing conclusion for `letf_quadratic_bound.py`**: both the forward
(regime-forecast) and backward (risk-budget-guard) uses of this module have
now been tested and rejected. The module's only defensible role in this
codebase remains its original one -- a research-only diagnostic / post-hoc
explanatory framework, not a live trading signal in either direction.
